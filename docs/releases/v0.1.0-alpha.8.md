# River 0.1.0-alpha.8

Completion-criterion history, explicit report links and repository verification guides for River’s native macOS app. The interface is currently in Korean.

**[Download the Apple Silicon DMG](https://github.com/ictechgy/river/releases/download/v0.1.0-alpha.8/River-0.1.0-alpha.8-macos-arm64.dmg)** · [All release assets](https://github.com/ictechgy/river/releases/tag/v0.1.0-alpha.8)

## Changes

- Give each completion criterion a durable ID. Reordering preserves identity, editing advances its revision, and duplication creates a new ID. Deleted criteria retain their earlier history and report bindings.
- Link human or AI reports to explicitly selected criteria. Keep copied criterion text and revision, report completion/tool status, provider/model and literal artifact references. Historical reports and app Git checks stay unlinked.
- Separate recording-time code observations from the HEAD or change snapshot a reviewer says they examined. Missing claims stay unknown; incomplete reports, tool errors and changed or deleted criteria remain visible. Matching hashes do not certify execution, criterion fulfillment or approval.
- Register repository verification procedures or feature-map references. Read one document explicitly as bounded plain text, optionally pin its SHA-256, then compare it on a later read. Documents are not executed or automatically included in AI handoffs.
- Keep the normal task pane compact with expandable criterion links, guide references and report details. Retrieve recent records through one indexed query rather than a query for every report. This is a query-count improvement, not a large-repository latency benchmark.

These implement the first three priorities from the earlier AI-DLC/pstack research and advisor discussion. No new provider consensus is claimed for this implementation. See the [task workflow guide](https://github.com/ictechgy/river/blob/v0.1.0-alpha.8/docs/task-workflow.md) and [research and boundaries](https://github.com/ictechgy/river/blob/v0.1.0-alpha.8/docs/ai-workflow.md).

## Install and compatibility

Alpha.6 and later can check **River → 업데이트 확인…**. Earlier versions need one manual installation: open the DMG, drag River.app into Applications, eject the image, then launch River. Download, installation and restart require user action. Save session drafts first; active work postpones restart.

| Item | This release |
| --- | --- |
| Architecture | Apple Silicon, `arm64` |
| Declared minimum | macOS 14 |
| Tested runtime | macOS 27.0.1; macOS 14–26 remains unverified |
| Bundle version | `0.1.0`, build `9`; full version `0.1.0-alpha.8` |
| Updates | Sparkle `2.10.0`; signed feed/archive; user-controlled installation |

The app, embedded updater/engine and DMG are Developer ID-signed. Executables use hardened runtime and secure timestamps. Apple notarization is **not completed**, so first launch may be blocked. Review Apple’s [Open Anyway instructions](https://support.apple.com/en-us/102445) if you choose to trust this alpha. Apple command-line Git is required; remote operations require Git 2.41 or later. The built-in example additionally needs `python3`.

Legacy persisted context and receipt bodies remain unchanged; v2 data uses separate tables and RPCs. After upgrade, the new engine rejects legacy context saves. A sequential legacy-engine rewrite is shown as a compatibility conflict; explicit reset creates fresh IDs while preserving earlier history. Do not run different engine versions concurrently against one journal. The guide explains the recovery path.

## Verification and limits

**218 Swift tests** and **141 Rust tests** pass, along with Rust formatting and Clippy checks. Coverage includes duplicate/reordered/deleted criterion identity, immutable report bindings, stale and concurrent writes, compatibility conflicts, report completion/basis separation, guide repository targeting, bounded text reads, unsafe paths, symlink races and special files. Unchanged Python sources retain alpha.6’s **56 Python** test validation.

Native synthetic scenarios use the real Rust service for saving, guide reading and pinning, report linking, edits and reconnects. Screens are rendered offscreen with SwiftUI/AppKit. These are not OS-input/clipboard/VoiceOver certification, older-macOS testing or large-repository benchmarks. Update feed/archive checks do not certify an OS-driven installation/relaunch.

- Recent evidence contains at most 50 records across the task; history summaries contain the latest 10 versions. Missing recent evidence does not establish absence across all history.
- Criterion links and claimed examined states are author-supplied reports. River does not infer fulfillment, observe external AI execution, or approve integration.
- Guide reads accept regular UTF-8 `.md`, `.txt`, `.mdc` and `.rst` files up to 64 KiB inside the selected repository/worktree. Includes, commands, URLs and document instructions are not followed. Pins compare bytes only when explicitly read again.
- App Git checks cover tracked hygiene/conflicts/in-progress state, not build/test success, untracked content or submodules. No automatic AI execution, merge or deployment is added. Existing [limitations](https://github.com/ictechgy/river/blob/v0.1.0-alpha.8/docs/limitations.md) remain. The project’s license is undecided (`UNLICENSED`).
