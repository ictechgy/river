# River 0.1.0-alpha.7

Current-folder evidence summaries and verification-request drafts for River’s native macOS app. The interface is currently in Korean.

**[Download the Apple Silicon DMG](https://github.com/ictechgy/river/releases/download/v0.1.0-alpha.7/River-0.1.0-alpha.7-macos-arm64.dmg)** · [All release assets](https://github.com/ictechgy/river/releases/tag/v0.1.0-alpha.7)

## Changes

- Show current-folder evidence gaps and the next useful check in task information. Distinguish missing intent, unavailable observations, failed or uncertain checks, and changed code or requirements. Use journal order even if the clock moves backwards.
- Keep recent recorded failures visible when their current applicability needs rechecking. Display the recent-record scope and separate author reports from app-observed Git checks. Expand the history only when needed.
- Include the same summary and next check for each repository in handoff, preserving unknown and unprepared sibling states.
- Choose **인수인계** or **검증 요청** from the existing draft action. Verification requests ask for actual behavior, inspectable evidence and explicit unexecuted checks. Preview and edit before copying; changing location discards the old preview. River does not invoke AI or execute draft commands.

These changes follow primary-source AI-DLC/pstack research and actual Claude, Grok and Devin discussion. Agy calls were quota-blocked and did not produce advice. See [workflow direction and boundaries](https://github.com/ictechgy/river/blob/v0.1.0-alpha.7/docs/ai-workflow.md).

## Install and compatibility

Alpha.6 users can check **River → 업데이트 확인…**. Alpha.5 and earlier need one manual installation: open the DMG, drag River.app into Applications, eject the image, then launch River. Download, installation and restart require user action. Save session drafts first; active work postpones restart.

| Item | This release |
| --- | --- |
| Architecture | Apple Silicon, `arm64` |
| Declared minimum | macOS 14 |
| Tested runtime | macOS 27.0.1; macOS 14–26 remains unverified |
| Bundle version | `0.1.0`, build `8`; full version `0.1.0-alpha.7` |
| Updates | Sparkle `2.10.0`; signed feed/archive; user-controlled installation |

The app, embedded updater/engine and DMG are Developer ID-signed. Executables use hardened runtime and secure timestamps. Apple notarization is **not completed**, so first launch may be blocked. Review Apple’s [Open Anyway instructions](https://support.apple.com/en-us/102445) if you choose to trust this alpha. Apple command-line Git is required; remote operations require Git 2.41 or later. The built-in example additionally needs `python3`.

## Verification and limits

**190 Swift tests** pass, including evidence scope/freshness, clock reversal, recorded-failure visibility, quoted request content and ServiceClient handoff regressions. Unchanged Python and Rust sources retain alpha.6’s **56 Python** and alpha.5’s **119 Rust** test validation. Native synthetic checks use the real Rust service and offscreen SwiftUI/AppKit rendering. These are not OS-input/clipboard/VoiceOver certification, older-macOS testing or large-repository benchmarks. Update parser/feed checks do not certify an OS-driven installation/relaunch.

- Evidence queries contain the latest 50 records across the task. A missing recent match does not establish absence across all history.
- App checks cover tracked Git hygiene/conflicts/in-progress state, not build/test success, untracked content, submodules, criterion fulfillment or merge readiness.
- Criteria remain author text; per-criterion evidence links and actually examined-state report fields are not implemented. Drafts contain collected observations, not a live integration approval.
- Existing Git/remote and late-update-cancellation reconnect limits remain in [current limitations](https://github.com/ictechgy/river/blob/v0.1.0-alpha.7/docs/limitations.md). No automatic AI execution, merge or deployment is added. The project’s license remains undecided (`UNLICENSED`).
